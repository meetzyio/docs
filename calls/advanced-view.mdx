The **Advanced Calls View** (`/calls-v2`) is the new version of the Calls page, built for teams that need deeper control over how call data is displayed, filtered, and audited. It introduces a fully configurable column manager (including dynamic input/output columns, pinning, and a recovered **Evaluations** column), a **Views** menu with both predefined and custom saved views, a single-row filter bar with agent, tag, status, suspicious-call, and OK/KO verdict filters, a call statistics summary bar with transfer-time totals, a manual refresh control, an OK/KO review workflow with audit notes, inline tag editing, full or selective Excel exports, and a built-in recording player with a real waveform and previous/next navigation between calls.

<Info>
The Advanced Calls View is rolling out alongside the classic Calls page. You can switch between the two at any time using the banner at the top of the page.
</Info>

## Switching between views

When you open the Advanced Calls View, you'll see a migration banner at the top of the page confirming you're on the new experience.

- The banner reads **"You're viewing the new Calls page."**, with a **Switch back to the classic view** link right next to it — click it to return to the original Calls page (`/calls-old`) at any time.
- The banner is always visible at the top of the page, so you're never in doubt about which version of the Calls page you're looking at.
- Your filters, column layout, and saved views on the Advanced Calls View are stored independently, so switching back and forth won't affect either page.

<Warning>
The Advanced Calls View is under active development. If something doesn't behave as expected, use the classic view as a fallback while we continue improving it.
</Warning>

## Configurable and pinnable columns

Unlike the classic Calls page, the Advanced Calls View lets you fully customize which columns appear in the table, in what order, and which ones stay anchored in place.

<Steps>
  <Step title="Open the Columns panel">
    Click the **⚙️ Columns** button in the top-right corner of the page to open the column manager.
  </Step>
  <Step title="Show or hide columns">
    Toggle any column on or off. This includes standard fields (status, duration, agent, tags, evaluations) as well as **dynamic columns** discovered automatically from your call inputs and outputs.
  </Step>
  <Step title="Reorder columns">
    Drag columns into the order that makes the most sense for your workflow.
  </Step>
  <Step title="Pin important columns">
    Click the **pin** icon next to any column to anchor it. Pinned columns are grouped together and stuck to the **right edge** of the table, so they stay visible no matter how many other columns you add or how far you scroll horizontally. **Reviewed** and **Actions** are pinned by default, and you can pin any additional column — such as **Tags** or a dynamic output field you check on every call — the same way.
  </Step>
  <Step title="Reset to defaults">
    If you want to start over, click **Reset to default** inside the column manager to discard your custom visibility, order, and pinning, restoring the platform's original column layout.
  </Step>
</Steps>

### Evaluations column

The **Evaluations** column shows which evaluation criteria a call met, mirroring the column that already existed on the classic Calls page.

<Info>
Evaluations previously existed in the classic view but hadn't been migrated to the Advanced Calls View, so it was missing here and couldn't even be turned on from the column manager. It's now available like any other column and, since it's information many teams audit daily, it's **enabled by default** — including for anyone who already had a saved column layout from before this fix, which is automatically upgraded to include it.
</Info>

### Dynamic columns from inputs and outputs

The Advanced Calls View scans a batch of your loaded calls and automatically discovers structured fields captured on each call's **input parameters** and **agent output**, turning them into selectable columns without any manual setup.

- Every dynamic column is clearly labeled with its **source** — `input` or `output` — so you always know where the value comes from, and which agent it belongs to when relevant.
- A handful of internal input fields (like `playbook_id`, `voice_id`, `temperature`, or `record`) are excluded automatically, since they're configuration details rather than meaningful call data.
- Nested objects and arrays are inspected up to a couple of levels deep, so fields buried inside a JSON output (for example inside a `metadata` object) can still surface as their own columns.
- If the same field appears at different paths across calls — for example an agent update that moved a field from the root of the output into a `metadata` object — the column still resolves and displays the value correctly for both older and newer calls, so you don't end up with the value silently missing or duplicated near-identical columns for what's really the same field.

<Info>
Dynamic fields are re-discovered as new calls load, so new fields introduced by an updated agent version show up as selectable columns automatically, without needing a page refresh or manual configuration.
</Info>

<Warning>
Resetting columns cannot be undone. If you rely on a custom layout, consider saving it as a view first (see below) before resetting.
</Warning>

## Views

The **👁️ Views** menu in the top-right corner is where you switch between different column-and-filter layouts. It's split into two sections: a set of **predefined views** maintained by Meetzy, and **My views** — the layouts you save yourself. The name of whichever view is currently active is always shown next to the **Views** button, so you know at a glance which layout you're on.

### Predefined views

Predefined views are ready-made layouts covering common review tasks, so you don't have to build a configuration from scratch for everyday use cases:

- **Call audit** — a review-focused layout showing the call date, agent, caller, status, duration, tags, and recording, sorted by most recent first. Ideal for day-to-day quality checks.
- **Latency monitoring** — surfaces the average and maximum AI response latency alongside a latency sparkline, sorted by average latency descending, so the slowest calls float to the top.
- **Compact overview** — a stripped-down layout with just the date, agent, caller, status, and duration, for quickly scanning volume without the extra detail.
- **Transfers & escalations** — highlights transferred and ended calls together with tags and the call summary, useful for reviewing how escalations were handled.

Click any predefined view's name to apply it instantly.

<Info>
Predefined views can be applied as many times as you like, but they can't be renamed or deleted — they're shared starting points, not personal views. If you want to tweak one, apply it first and then save your adjusted version under a new name in **My views**.
</Info>

### Custom saved views

Once you've configured your columns, pins, and filters the way you like, you can save that configuration as a **named view** and switch back to it whenever you need.

<Steps>
  <Step title="Configure your table">
    Set up your columns, pinning, filters, and sorting exactly how you want them — starting from scratch or from a predefined view.
  </Step>
  <Step title="Open the Views menu">
    Click **👁️ Views** in the top-right corner.
  </Step>
  <Step title="Save the current configuration">
    Type a name for your view in the input field and click **Save current**. Give it something memorable, like "Suspicious calls this week" or "My agent's calls".
  </Step>
  <Step title="Apply a saved view">
    Open the Views menu at any time and click a view's name — predefined or your own — to instantly apply it. The active view is highlighted in green with a checkmark next to it, and its name appears next to the **Views** button. Use the **✕** icon next to one of your own views to delete it.
  </Step>
</Steps>

<Info>
Saved views are stored per user, so each teammate can build their own set of named views — on top of the same shared predefined views — without affecting anyone else's setup. If you don't have any saved views yet, the **My views** section simply shows a short note letting you know the list is empty.
</Info>

## Filtering calls

The filter bar is organized into a single, evenly spaced row of controls followed by the status chips, making it easy to scan and combine filters.

### Date range

Choose from common presets (Today, Yesterday, Last 7 days, This month, etc.) or define a fully custom start and end date and time.

<Info>
Day-based presets here (such as "Today" or "Last 7 days") end at 23:59:59 of the last day, instead of rolling into 00:00 of the following day.
</Info>

### Agents

The agent filter uses a chip-based multi-select:

- Start typing an agent's name to search.
- Click an agent from the dropdown to add it as a chip.
- Remove a chip by clicking the **✕** on it, or clear all selected agents at once.
- Leaving the filter empty shows calls from all agents.

### Tags

Tags work the same way as agents — search, select, and manage them as chips. This makes it easy to combine multiple tags to narrow down a specific segment of calls.

- The tag suggestions dropdown is populated from every tag currently used across your calls, so it stays in sync as new tags are created.
- You can combine several tags at once — a call matching **any** of the selected tags is included, making it easy to group related segments (for example, several campaign tags) into a single filtered view.
- Tags added, renamed, or removed through the inline tag editor (see below) are reflected in this filter's suggestions right away.

### Status

Filter by one or more call statuses, including Open, Closed, No answer, Voicemail, **Silence**, Busy, Failed, Transferred, and Blocked.

<Info>
**Silence** identifies calls where the line connected but no real conversation took place — the call ended without a transcript worth reviewing. It's surfaced as its own selectable status chip, separate from Failed or No answer, so you can isolate these calls specifically instead of digging for them inside a broader status group.
</Info>

### Suspicious calls

The **Suspicious calls** filter is a one-click way to surface calls that are worth a closer look. It's a client-side filter that flags a call as suspicious if **any** of the following are true:

- The AI response latency was unusually high.
- The call ended with a problematic status (`no-answer`, `failed`, or `blocked`).
- The call has no transcript at all.

<Info>
This is intentionally an **OR** condition rather than an **AND** condition. Combining several individual filters (like status) would only show calls matching *all* conditions, which tends to under-match what auditors actually want to review first. The Suspicious calls filter is designed to catch anything that looks off, from any angle.
</Info>

<Info>
Because calls with the **Silence** status have no meaningful transcript by definition, they're naturally caught by the "no transcript at all" condition above — so turning on **Suspicious calls** is also a quick way to spot silent calls without setting up a status filter first.
</Info>

The suspicious filter is a single toggle placed alongside the rest of the filter bar — it doesn't require selecting a status or configuring anything else first. Turn it on to instantly narrow the table down to calls worth a closer look, and turn it off to go back to your regular filtered view. It also combines cleanly with the other filters: for example, enabling **Suspicious calls** together with an **Agent** filter shows you only that agent's calls that need attention, without having to build a multi-condition filter manually.

### Review verdict (OK/KO)

A dedicated verdict filter lets you narrow the table down to only the calls your team has already reviewed and marked with an outcome:

- Select **OK** to see everything approved during review.
- Select **KO** to pull up everything flagged as problematic.
- Leave it unset to show calls regardless of verdict, including calls that haven't been reviewed at all.

This is especially handy at the end of a review session — quickly pull up every call marked **KO** to make sure each one has a follow-up note, or check every **OK** call before sharing a "clean" batch with a manager or client. It also combines with the other filters, for example to check the **KO** calls for a single agent or tag.

## Call statistics & transfer time summary

Above the table, a summary bar shows aggregate statistics computed **server-side** across **every call matching your current filters and date range** — not just the calls currently loaded on screen. This makes it a reliable, at-a-glance health check even before you scroll through a single row.

The summary includes:

- **Total calls**, **closed calls**, and **voicemail calls** in the selected range.
- **Average duration** across all matching calls.
- **Average** and **P90 AI response latency**, useful for spotting whether slowness is a rare outlier or a widespread pattern.
- **Transfer time totals**, shown as two separate summary cards for **inbound** and **outbound** transferred calls, so you can see at a glance how much total time was spent on transfers in each direction.

<Info>
The transfer time totals only account for time spent in the transferred portion of a call, and are aggregated separately for inbound and outbound calls since the two typically have very different transfer patterns and costs. This is calculated server-side across the full filtered date range, so the numbers stay accurate even when you're only looking at a page of 50 or 100 loaded calls.
</Info>

<Info>
Because these statistics respect your active filters, you can combine them with the **Agents**, **Tags**, or **Status** filters to check, for example, the average transfer time for a single agent, or the total inbound transfer seconds for only the calls tagged as escalations.
</Info>

## Refreshing the table

The table is refreshed **manually**, using a dedicated **↻ Refresh** button near the top of the table.

- Click **Refresh** whenever you want to pull in the newest calls matching your current filters, date range, and sort order.
- Newly arrived calls that weren't in the table before are briefly highlighted, so they're easy to spot right after a refresh.
- Refreshing respects your current filters, sort order, and scroll position — it won't reset or jump you back to the top of the table.

<Info>
This replaces the previous automatic **Live** polling mode. Rather than the table quietly refreshing itself in the background at adaptive intervals, you're now fully in control of when the table updates — click **Refresh** whenever you want the latest calls, and the table stays perfectly still in between clicks. This also removes any risk of a background refresh interrupting an in-progress edit, like a review note or tag you're in the middle of typing.
</Info>

<Tabs>
  <Tab title="When to refresh">
    Click **Refresh** right before starting a review session to make sure you're looking at the latest calls, or periodically while monitoring an ongoing campaign to check for new activity — especially combined with the **Suspicious calls** filter to catch anything that needs attention as soon as it shows up.
  </Tab>
  <Tab title="Why manual instead of automatic">
    A manual refresh keeps the table predictable while you work: your scroll position, open editors, and in-progress filters are never disturbed by a refresh you didn't ask for. You decide exactly when new data comes in.
  </Tab>
</Tabs>

## Review and audit workflow

Each row in the table includes a **Reviewed** control that lets your team track which calls have already been checked, an **OK/KO verdict**, and an optional audit note — all editable directly inline, without opening a separate modal. This column is pinned to the right edge of the table by default, so it stays visible no matter how many columns you've added.

<Steps>
  <Step title="Mark a call as reviewed">
    Click the review indicator on a call's row to toggle its reviewed status inline.
  </Step>
  <Step title="Set an OK/KO verdict">
    Once you've listened to or read through a call, click **OK** or **KO** to record your audit verdict. Clicking the same verdict again clears it. Setting a verdict automatically marks the call as reviewed; clearing the reviewed toggle also clears the verdict.
  </Step>
  <Step title="Add an audit note">
    Click the note icon to open a small inline editor and write context about why the call was flagged, resolved, or worth revisiting — for example, explaining why a call was marked KO.
  </Step>
  <Step title="Save automatically">
    The reviewed toggle, the verdict, and the note text are all saved automatically a moment after you stop interacting — no need to click a separate save button.
  </Step>
</Steps>

<Info>
Only one review note editor can be open at a time. Clicking outside the editor, or opening a note on another row, will close the current one.
</Info>

Use the **Review verdict (OK/KO)** filter described above to pull up everything you've already flagged during a session, or to double-check a batch of approvals before sharing them.

This review workflow is especially useful when combined with the **Suspicious calls** filter: click **Refresh** to catch new calls as they come in, flag the suspicious ones, review them one by one, record an OK/KO verdict with a note explaining the outcome, and mark them as reviewed once resolved. Save that exact combination of filters and columns as a custom view under **My views** so your team can jump straight back into it later.

<Info>
This same reviewed toggle, OK/KO verdict, and note editor are also available directly inside the recording player modal, so you can record your audit verdict right after listening to a call without switching back to the table.
</Info>

## Inline tag editing

The **Tags** column lets you manage a call's tags directly from the table, without opening the call's detail view.

<Steps>
  <Step title="Open the tag editor">
    Click into the Tags cell on any row to reveal the inline tag editor.
  </Step>
  <Step title="Add a tag">
    Start typing to search existing tags — an autocomplete dropdown suggests matching tags already used across your calls, so you can stay consistent instead of creating near-duplicate tags. Press **Enter** or select a suggestion to add it.
  </Step>
  <Step title="Rename a tag">
    Renaming isn't a separate action — remove the old tag chip and add the new one in its place. Since tag suggestions are shared across calls, the new name immediately becomes available as a suggestion for every other call going forward.
  </Step>
  <Step title="Remove a tag">
    Click the **✕** on any tag chip to remove it from the call.
  </Step>
  <Step title="Save automatically">
    Tag changes are saved as soon as you add or remove a chip — there's nothing else to confirm.
  </Step>
</Steps>

<Info>
Tags added or removed inline are immediately reflected in the **Tags** filter's suggestions, so newly created or renamed tags become searchable right away. The same add/remove tag editor is also available inside the recording player modal.
</Info>

## Recording player

Clicking a call's recording opens a dedicated player modal built specifically for reviewing audio quickly, with a real waveform rendered from the decoded audio rather than a generic progress bar.

<Tabs>
  <Tab title="Waveform & seeking">
    The waveform is built client-side from the actual audio data using the Web Audio API, so its shape reflects the real volume of the call rather than a placeholder animation. Click anywhere on the waveform to seek directly to that point in the recording.
  </Tab>
  <Tab title="Skip ±10s">
    Use the skip-back and skip-forward controls to jump exactly 10 seconds backward or forward — handy for re-listening to a specific exchange without scrubbing manually.
  </Tab>
  <Tab title="Playback speed">
    Choose a playback speed — 0.5×, 0.75×, 1×, 1.25×, 1.5×, or 2× — to slow down a tricky passage or speed through a long, uneventful call.
  </Tab>
</Tabs>

### Navigating between calls

Instead of closing the modal to move to another row, the player lets you step through calls directly from within it.

<Steps>
  <Step title="Use the arrow buttons">
    Click the **‹** and **›** icons in the modal header to jump to the previous or next call in your current filtered and sorted list.
  </Step>
  <Step title="Or use your keyboard">
    Press the **←** and **→** arrow keys to move between calls without touching the mouse — handy for quickly moving through a batch of flagged calls.
  </Step>
  <Step title="Reach the edges">
    The **‹** and **›** buttons are automatically disabled once you reach the first or last call in the list, so you always know when you've reviewed everything currently loaded.
  </Step>
</Steps>

<Info>
Moving to the next or previous call keeps the same modal open — the recording, transcript, and review controls all update in place, with a short slide transition indicating which direction you moved.
</Info>

<Info>
Keyboard shortcuts for navigating between calls are disabled automatically while you're typing in the note or tag input, so arrow keys behave normally while you're writing.
</Info>

<Info>
The player modal also includes the same **Reviewed**/**OK**/**KO** review controls and audit note found in the table, plus inline tag management — so you can complete most of a review session, including moving on to the next call, without ever leaving the recording view.
</Info>

## Exporting to Excel

The Advanced Calls View supports two export modes:

<Tabs>
  <Tab title="Export all filtered calls">
    Click **Export to Excel** to export every call currently matching your active filters, respecting your selected columns.
  </Tab>
  <Tab title="Export selected rows only">
    Select one or more rows using the row checkboxes, then click **Export selection (N)**. This exports only the calls you've selected, and always includes the **Reviewed** status, the **OK/KO verdict**, and the **audit note**, regardless of whether those columns are currently visible in the table.
  </Tab>
</Tabs>

<Info>
Selective export is ideal for sharing a curated set of reviewed or suspicious calls with a manager or client, without exposing your entire filtered dataset. Because the review status, verdict, and audit note are always included in this export, it doubles as a ready-made audit trail you can hand off as-is.
</Info>

<Info>
The **Export selection (N)** button only appears once you've selected at least one row, with the count updating live as you check or uncheck rows — so you always know exactly how many calls will be included before you export.
</Info>

<Warning>
Both export modes generate the file client-side based on the calls currently loaded in the table. If you're exporting all filtered calls, make sure you've loaded as many pages as you need before exporting, since the export won't reach beyond what's already been fetched into the table.
</Warning>

@HostListener('document:keydown', ['$event'])
onKeydown(event: KeyboardEvent): void {
  if (!this.isOpen) return;
  const target = event.target as HTMLElement | null;
  // Don't hijack arrow keys while the user is typing in the note/tag inputs.
  if (target && (target.tagName === 'INPUT' || target.tagName === 'TEXTAREA')) return;
  if (event.key === 'ArrowLeft') {
    event.preventDefault();
    this.goPrevious();
  } else if (event.key === 'ArrowRight') {
    event.preventDefault();
    this.goNext();
  }
}

goPrevious(): void {
  if (!this.hasPrevious) return;
  this.triggerNavAnimation('prev');
  this.previousCall.emit();
}

goNext(): void {
  if (!this.hasNext) return;
  this.triggerNavAnimation('next');
  this.nextCall.emit();
}
