# Call Details

Every call generates detailed data that helps you understand what happened during the conversation. The Call Details modal provides access to all information captured during the call.

## Opening Call Details

Click on any call row in the Call History table, or click the **View** button to open the details modal.

## Modal Layout

The Call Details modal is organized in a three-column layout:

| Panel | Content |
|-------|---------|
| ⬅️ Left | Input Parameters (JSON) |
| 📊 Center | Call Information |
| ➡️ Right | Output Response (JSON) |

## Input Parameters

The left panel displays the input JSON that was sent to initiate the call:

```json
{
  "phone": "+1234567890",
  "customer_name": "John Smith",
  "appointment_date": "2024-02-15",
  "custom_fields": {
    "order_id": "ORD-12345"
  }
}
```

### Features

- **Copy Button** - Copy the entire JSON to clipboard
- **Syntax Highlighting** - Color-coded JSON for readability
- **Expandable** - Scroll through large input payloads

## Call Information

The center panel shows key metadata about the call:

| Field | Description |
|-------|-------------|
| Call ID | Unique identifier (monospace, copyable) |
| Status | Current status with colored badge |
| Success | ✓ Yes or ✗ No indicator |
| Playbook | Agent name that handled the call |
| Duration | Call length in human-readable format |
| From | Origin phone number |
| To | Destination phone number |
| Email | Contact email (if provided) |
| Created Time | Timestamp when call was initiated |
| Tags | Labels applied to this call |

### Status Badges

| Status | Color | Description |
|--------|-------|-------------|
| completed | 🟢 Green | Call finished normally |
| in-progress | 🔵 Blue | Call is currently active |
| failed | 🔴 Red | Call encountered an error |
| transferred | 🟣 Purple | Call was transferred |
| no-answer | ⚪ Gray | Recipient didn't answer |

## LLM Model Usage

Meetzy runs on ElevenLabs' LLM cascade, which can automatically fall back to a different model mid-call if the primary model is slow or unavailable. The **LLM** block in the Call Information panel gives you visibility into exactly which models handled the conversation.

### Models Used

At the top of the block, you'll see a list of every distinct model that participated in the call, in the order they were first used:

```
gpt-4o-mini → gpt-4o → claude-3-5-sonnet
```

<Info>
If only one model appears, the cascade never needed to fall back — the primary model handled the entire call. If more than one model appears, ElevenLabs degraded to a secondary model at some point during the conversation.
</Info>

<Warning>
For calls made before **July 29, 2026**, this list falls back to the single `model_used` field, since per-turn tracking wasn't available yet. In that case, you'll only see one model, even though a cascade may still have been active behind the scenes.
</Warning>

### Per-Turn Breakdown (Cascade Detail)

Below the model list, click **Show Detail** to expand a collapsible, second-by-second breakdown of the cascade. This detail is collapsed by default to keep the modal compact.

Each row in the expanded view represents one conversational turn and shows:

| Column | Description |
|--------|-------------|
| Time | Elapsed seconds (`t`) since the call started |
| Model(s) | Which model(s) generated output for that turn |
| Tokens | Output tokens produced by each model at that turn |

If a turn used more than one model — for example, the primary model started responding but was interrupted by a fallback — both models are listed together, joined with `+`.

<Steps>
  <Step title="Locate the LLM block">
    Open any completed call's details and find the **LLM** section in the center panel, below the core call metadata.
  </Step>
  <Step title="Review the models used">
    Check the summary list to quickly spot whether the cascade degraded during the call.
  </Step>
  <Step title="Expand the detail">
    Click **Show Detail** to reveal the per-turn table and identify exactly when the switch happened.
  </Step>
  <Step title="Collapse when done">
    Click **Hide Detail** to collapse the breakdown again and keep the modal easy to scan.
  </Step>
</Steps>

<Info>
Cascade degradation is not necessarily an error — it means ElevenLabs automatically routed the conversation to keep latency low. Use this data to spot patterns (e.g., a model that degrades frequently) and adjust your agent configuration if needed.
</Info>

## Output Response

The right panel displays the output JSON containing all data captured during the call:

```json
{
  "transcription": "Agent: Hello, this is Sarah from...",
  "summary": "Customer confirmed appointment for...",
  "sentiment": "positive",
  "output_params": {
    "appointment_confirmed": true,
    "preferred_time": "morning",
    "callback_requested": false
  },
  "evaluations": {
    "successful_greeting": true,
    "collected_requirements": true
  }
}
```

### Output Contents

<AccordionGroup>
  <Accordion title="Transcription">
    Full conversation transcript between the agent and the caller, with speaker labels.
  </Accordion>
  <Accordion title="Summary">
    AI-generated summary of the call's key points and outcomes.
  </Accordion>
  <Accordion title="Output Parameters">
    Structured data extracted from the conversation based on your Output Settings configuration.

  <Accordion title="Evaluations">

  </Accordion>
  <Accordion title="Tool Calls">
    If the agent invoked any tools or webhooks, their requests and responses are included.
  </Accordion>

## Recording Playback

If call recording is enabled, clicking the recording icon opens a dedicated **Call Recording** modal with a full-featured player on one side and a rich, per-turn transcript on the other.

### Waveform Player

Unlike a plain `<audio>` progress bar, the player renders a **real, interactive waveform** generated directly from the decoded audio — not a placeholder animation. When the recording loads, the audio is decoded via the Web Audio API and sampled into 100 amplitude bars, so the shape you see actually reflects the call's audio (silences, loud segments, etc.).

<CardGroup cols={2}>
  <Card title="Click-to-seek" icon="hand-pointer">
    Click anywhere on the waveform to jump to that point in the call. The played portion is highlighted in a different color as the call progresses.
  </Card>
  <Card title="+/-10s skip" icon="rotate">
    Use the back/forward buttons to jump exactly 10 seconds, ideal for re-listening to a specific exchange without scrubbing manually.
  </Card>
  <Card title="Playback speed" icon="gauge">
    Choose between 0.5x, 0.75x, 1x, 1.25x, 1.5x, and 2x to review calls faster or slow down a hard-to-understand segment.
  </Card>
  <Card title="Download" icon="arrow-down-to-line">
    Download the original recording file for offline access, sharing, or permanent storage.
  </Card>
</CardGroup>

<Info>
The waveform is computed once per call and cached for the session — reopening the same recording doesn't require re-decoding the audio.
</Info>

### Enriched Transcript

Next to the player, the transcript is rendered turn-by-turn (not as a single wall of text). Each turn shows its elapsed time in the call, and agent turns carry two kinds of expandable detail sourced directly from the underlying ElevenLabs conversation: a **response time breakdown** and, when applicable, **tool call details**.

#### Turn Latency Breakdown

Every agent turn shows a **"Replied in Xs"** summary next to its message. Clicking it expands a per-turn latency breakdown that answers the question auditors actually care about: *the agent took this long to answer — where did that time go?*

The breakdown splits the response time into a stacked bar with the following stages, shown in the order they occur in the pipeline:

| Stage | Meaning |
|-------|---------|
| Understanding speech | Speech-to-text (ASR) latency — how long it took to transcribe what the caller said |
| Model thinking | Time to first byte from the LLM — how long the language model took to start generating a response |
| Generating voice | Text-to-speech (TTS) latency — how long it took to synthesize the agent's audio |
| Other overhead | Any small residual not accounted for by the stages above, rather than being silently dropped |

<Info>
A separate **"Waiting on purpose"** segment may also appear. This is not slowness — it's the agent deliberately holding back before speaking (for example, waiting a few seconds before asking "are you still there?"). It's called out separately, with a note below the chart, so a deliberate pause isn't mistaken for a performance problem. The "Replied in" headline itself always excludes this wait time.
</Info>

Each stage in the breakdown shows its duration and percentage of the total, along with the LLM model that generated the response for that turn.

<Steps>
  <Step title="Scan the turn">
    Each message bubble shows its elapsed time in the call, plus a "Replied in Xs" summary on agent turns.
  </Step>
  <Step title="Expand the latency breakdown">
    Click **Replied in Xs** to reveal the stacked bar showing how the response time splits across understanding speech, model thinking, generating voice, and any deliberate wait.
  </Step>
  <Step title="Expand tool calls">
    Click a **🔧 tool name** badge to reveal the exact parameters sent to the tool and the result (or error) it returned.
  </Step>
</Steps>

#### Tool Call Details

If the agent invoked a tool or function during a turn, a **🔧 tool name** badge appears next to that turn. Expanding it shows:

- **Parameters** — the exact JSON payload sent to the tool for that call
- **Result** — the value the tool returned, or the error details if the call failed

This lets you verify not just *that* a tool was called, but exactly *what* was sent and *what* came back, without leaving the recording view.

<Info>
This view mirrors what ElevenLabs' own conversation view shows, since this per-turn detail (latency metrics, model attribution, tool payloads) isn't persisted in Meetzy's database — it's fetched live from ElevenLabs when you open the recording.
</Info>

<Warning>
If the underlying ElevenLabs conversation is no longer available (for example, an old or purged call), the modal automatically falls back to a **plain transcript** view — the message bubbles are still shown, but without latency breakdowns, model detail, or tool call/result cards. A short notice appears above the transcript in this case.
</Warning>

<Warning>
Call recordings are stored for a limited time based on your plan. Download important recordings for permanent storage.
</Warning>
