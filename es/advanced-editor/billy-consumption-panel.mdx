<Info>
El panel de consumo Billy proporciona una vista integral de tu consumo actual de minutos facturables, permitiendo el seguimiento y análisis detallado de los costos por asistente.
</Info>

## Descripción General

El panel de consumo Billy es un componente flotante anclado a la parte inferior del editor avanzado. Ofrece:

- **Seguimiento en tiempo real** del consumo de minutos
- **Barra de progreso del paquete de minutos** contratado (cuando aplica)
- **Desglose detallado** por asistente
- **Filtros flexibles** por período, con selector desplegable
- **Ticker de mensajes** informativos cuando el panel está colapsado
- **Gráficos históricos** de facturación para administradores
- **Indicadores visuales** del estado del servicio
- **Panel expandible/colapsible** para optimizar el espacio

## Barra de Progreso del Paquete de Minutos

<Info>
Esta barra solo se muestra en vistas de cliente cuyo perfil Billy tiene configurada una asignación mensual de minutos contratados (`minutes_package`). No aparece en la vista de administrador ni si el cliente no tiene un paquete configurado.
</Info>

La barra de progreso ofrece un resumen visual inmediato del consumo del período actual:

- **Etiqueta de sección**: "Paquete de minutos" en tipografía discreta y mayúsculas espaciadas
- **Contador numérico**: Muestra minutos consumidos frente al total contratado (`consumidos / contratados min`)
- **Barra de progreso animada**: Se rellena de forma proporcional al porcentaje de uso, con transición suave
- **Cambio de color dinámico**:
  - **Verde esmeralda**: Consumo dentro del límite contratado
  - **Rojo**: Consumo que ha superado la asignación contratada (`over_allowance`)
- **Mensaje contextual** debajo de la barra:
  - Si queda margen disponible: "X min restantes este período"
  - Si se ha excedido el paquete: "Paquete excedido en X min"

### Estructura de Datos

```typescript
interface MinutesPackage {
  consumed: number;
  contracted: number;
  remaining: number;
  usage_percent: number;
  over_allowance: boolean;
}
```

<Warning>
Cuando `over_allowance` es `true`, la barra cambia a color rojo para alertar visualmente al usuario de que se ha superado el paquete contratado, incluso si el porcentaje visual de la barra permanece al máximo.
</Warning>

## Sistema de Filtros Avanzados

### Filtros por Período

El panel incluye un sistema de filtros completo que permite:

- **Períodos predefinidos**: Basados en el día de inicio del período de facturación (8 períodos históricos)
- **Rangos personalizados**: Selección libre de fechas de inicio y fin
- **Validación en tiempo real**: Verificación automática de rangos de fechas válidos
- **Sincronización automática**: Los filtros se sincronizan con los datos de consumo recibidos

### Configuración de Filtros

<Warning>
Los filtros de fecha deben respetar la lógica temporal:
- La fecha de inicio no puede ser posterior a la de fin
- Ambas fechas son requeridas para rangos personalizados
- Los mensajes de error se muestran en tiempo real
</Warning>

El sistema de filtros ofrece una sección expandible que permite:

- **Selector de período**: Menú desplegable con períodos predefinidos calculados dinámicamente
- **Campos de fecha personalizados**: Inputs de fecha para rangos específicos
- **Botón "Aplicar"**: Para confirmar rangos personalizados
- **Validación inmediata**: Feedback visual de errores de validación

### Filtro de Período Desplegable

El selector de período se implementa como un menú desplegable (`dropdown`) totalmente accesible:

<Steps>
  <Step title="Botón desencadenante">
    Muestra la etiqueta del período actualmente seleccionado y un icono de flecha que rota al abrir el menú. Se deshabilita mientras el panel está cargando datos.
  </Step>

  <Step title="Lista de opciones">
    Al abrirse, despliega una lista (`role="listbox"`) con todos los períodos disponibles, posicionada sobre el botón para evitar que se corte en la parte inferior de la pantalla.
  </Step>

  <Step title="Selección con indicador visual">
    Cada opción incluye un icono de verificación que solo es visible en el período actualmente seleccionado (`role="option"`, `aria-selected`).
  </Step>

  <Step title="Cierre automático">
    El menú se cierra automáticamente al seleccionar una opción, al colapsar la sección de filtros, o al hacer clic fuera del componente.
  </Step>
</Steps>

<Info>
El cierre del menú al hacer clic fuera se gestiona mediante un listener global de clics en el documento, que verifica si el elemento pulsado pertenece al contenedor del desplegable (`data-billy-period-dropdown`).
</Info>

### Gráfico Histórico de Facturación

El gráfico histórico se activa únicamente para administradores mediante una sección expandible, y ofrece:

- **Carga diferida**: Solo se carga cuando el administrador lo solicita por primera vez
- **Visualización interactiva**: Gráfico de barras con información detallada mes a mes
- **Manejo de estados**: Loading, error y éxito claramente diferenciados
- **Cacheo en memoria**: Una vez cargado el historial, volver a abrir la sección no repite la petición a la API
- **Optimización de rendimiento**: Destrucción automática del gráfico al cambiar de contexto o al salir de la vista de administrador

```typescript
async toggleHistoryChart(): Promise<void> {
  this.showHistoryChart = !this.showHistoryChart;

  if (!this.showHistoryChart) {
    return;
  }

  if (!this.historyLoaded) {
    await this.loadBillingHistory();
    return;
  }

  setTimeout(() => void this.renderHistoryChart());
}

async loadBillingHistory(): Promise<void> {
  this.historyLoading = true;
  this.historyError = false;

  try {
    const response = await this.apiService.getBillyBillingHistory();
    if (response.success) {
      this.billingHistory = response.data.months || [];
      this.historyLoaded = true;
      this.refreshTicker();
      setTimeout(() => void this.renderHistoryChart());
    } else {
      this.historyError = true;
    }
  } catch (err) {
    console.error('Billy billing history panel error:', err);
    this.historyError = true;
  } finally {
    this.historyLoading = false;
  }
}
```

<Info>
Al cargar correctamente el historial de facturación, sus datos también se incorporan al conjunto de mensajes del ticker, enriqueciendo la información mostrada cuando el panel está colapsado.
</Info>

## Ticker de Mensajes

<Info>
El ticker de mensajes es una funcionalidad exclusiva del estado colapsado del panel: muestra información relevante de forma rotativa sin necesidad de expandir el panel completo.
</Info>

Cuando el usuario colapsa el panel, en lugar de ocultar toda la información, se activa un ticker que va mostrando mensajes breves de forma secuencial:

### Comportamiento del Ticker

<Steps>
  <Step title="Activación">
    El ticker se inicia automáticamente al colapsar el panel (`toggleCollapsed()`), reiniciando el índice del mensaje mostrado y forzando su visibilidad.
  </Step>

  <Step title="Rotación temporizada">
    Los mensajes rotan automáticamente cada 4,5 segundos (`TICKER_INTERVAL_MS`), recorriendo de forma cíclica el array `tickerMessages`.
  </Step>

  <Step title="Transición con fundido">
    Antes de cambiar de mensaje, el texto actual se desvanece brevemente (220 ms, `TICKER_FADE_MS`) para dar paso al siguiente mensaje con una transición suave.
  </Step>

  <Step title="Desactivación">
    El ticker se detiene automáticamente al expandir el panel de nuevo, liberando el temporizador para evitar fugas de memoria.
  </Step>
</Steps>

### Contenido de los Mensajes

Los mensajes del ticker se recalculan (`refreshTicker()`) cada vez que:

- Se carga con éxito el consumo actual del período
- Se carga con éxito el historial de facturación (solo administradores)

Esto permite que, incluso con el panel colapsado, el usuario reciba información actualizada sobre su consumo, su paquete de minutos o hitos relevantes de facturación sin necesidad de expandir el panel.

```typescript
  try {
    localStorage.setItem(this.COLLAPSED_KEY, String(this.collapsed));
  } catch {
    // Ignore storage failures in private browsing or restricted contexts.
  }
```

<Warning>
Si el array `tickerMessages` está vacío (por ejemplo, cuando no hay datos de consumo visibles o se produjo un error al cargarlos), el ticker no se inicia y el panel colapsado no muestra ningún mensaje rotativo.
</Warning>

```typescript
private translateUnitLabel(label: string, units: number): string {
  const normalized = String(label || '').toLowerCase();
  const translations: Record<string, { singular: string; plural: string }> = {
    minute: { singular: 'minuto', plural: 'minutos' },
    call: { singular: 'llamada', plural: 'llamadas' },
    second: { singular: 'segundo', plural: 'segundos' },
    hour: { singular: 'hora', plural: 'horas' }
  };

  const translation = translations[normalized];
  if (translation) {
    return Math.abs(units) === 1 ? translation.singular : translation.plural;
  }

  return label;
}
```

## Performance y Optimización

### Carga Diferida

<Steps>
  <Step title="Inicialización">
    Solo se cargan los datos básicos de consumo al inicializar
  </Step>

  <Step title="Datos Históricos">
    Los gráficos históricos se cargan bajo demanda solo para administradores
  </Step>

  <Step title="Chart.js">
    La biblioteca de gráficos se carga únicamente cuando se necesita
  </Step>

  <Step title="Temporizadores del Ticker">
    Los temporizadores del ticker de mensajes solo se activan mientras el panel está colapsado, liberándose automáticamente al destruirse el componente (`ngOnDestroy`)
  </Step>
</Steps>

### Manejo de Errores

El panel implementa manejo robusto de errores:

- **Errores de API**: Mensajes descriptivos en español en la interfaz
- **Errores de localStorage**: Fallback silencioso
- **Errores de validación**: Feedback inmediato al usuario en español
- **Errores del historial de facturación**: Estado independiente (`historyError`) que no afecta al resto del panel

<Warning>
En contextos de navegación privada o con restricciones de almacenamiento, el panel funcionará correctamente pero no recordará el estado de expansión entre sesiones.
</Warning>

## Funcionalidades de Filtrado

### Sincronización de Filtros

El panel sincroniza automáticamente los filtros con los datos recibidos:

- **Detección de modo**: Identifica si el período es predefinido o personalizado
- **Construcción dinámica**: Genera opciones de período basadas en configuración
- **Persistencia de estado**: Mantiene la selección del usuario entre actualizaciones
- **Etiqueta activa**: El botón del desplegable siempre refleja la etiqueta del período efectivamente aplicado, incluso tras una actualización

### Validación de Fechas

<Steps>
  <Step title="Validación Básica">
    Verifica que ambas fechas estén presentes para rangos personalizados
  </Step>

  <Step title="Validación Temporal">
    Confirma que la fecha de inicio sea anterior o igual a la fecha de fin
  </Step>

  <Step title="Feedback Visual">
    Muestra mensajes de error claros en español cuando la validación falla
  </Step>

### Actualización Inteligente

El botón de actualización aplica el filtro apropiado:

- **Rango personalizado**: Si hay fechas personalizadas válidas
- **Período seleccionado**: Si hay un período predefinido activo
- **Sin filtros**: Carga datos del período actual por defecto

```typescript
async refreshCurrentFilter(): Promise<void> {
  if (this.dateMode === 'custom' && this.customStart && this.customEnd) {
    await this.applyCustomRange();
    return;

  const selectedPeriod = this.periodOptions.find((option) => option.key === this.selectedPeriodKey);
  if (selectedPeriod) {
    await this.onPeriodChange(selectedPeriod.key);
    return;
  }

  await this.loadConsumption();
}
```
